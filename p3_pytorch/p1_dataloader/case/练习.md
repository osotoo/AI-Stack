### 练习一：电商评论情感分析（NLP核心：处理变长文本）

**业务背景**：公司爬了一堆京东的商品评论数据，存在一个 `comments.csv` 文件里（字段：`user_id`, `comment_text`, `star_rating`）。你要把它做成能喂给模型的 Dataset。

**技术要求**：
1.  **数据清洗**：如果 `comment_text` 是空的，或者 `star_rating` 缺失，直接丢弃这条数据。
2.  **自定义 Dataset**：写一个 `ReviewDataset` 类继承 `Dataset`。在 `__getitem__` 里，使用 `transformers` 的 `AutoTokenizer`（比如 `bert-base-chinese`），把文本转成 `input_ids`。**如果评价分数（star_rating）大于等于4，标签设为1（好评），小于等于2设为0（差评），中间的3丢掉。**
3.  **核心考点（必做）**：文本有长有短。如果你直接 `DataLoader(batch_size=4)`，**绝对会报错**（形状不一致无法打包）。你需要写一个自定义的 `collate_fn`，在打包时，动态计算当前 Batch 里最长的那句话，把其他短句补齐（Padding）。

**提示**：这是企业里做文本分类、甚至微调大模型前**必须**掌握的基石。

### 练习二：企业私有知识库 RAG 数据切分（架构师必备）

**业务背景**：老板丢给你一个文件夹 `./company_docs/`，里面全是 `.txt` 格式的规章制度文档。你要把这些文档切碎（Chunking），变成一个个“问答对”，准备放进向量数据库。

**技术要求**：
1.  **自定义 Dataset**：写一个 `DocChunkDataset` 类。
2.  **`__init__` 逻辑**：读入文件夹里的所有 txt 文件。
3.  **`__getitem__` 逻辑**：这是一个**滑动窗口切分**练习。把一长段文本，按照 `chunk_size=200`（每次取200个字）切分。为了上下文连贯，要求**前后两个 Chunk 有 50 个字的交叠（Overlap）**。
4.  **返回值**：返回一个字典 `{"chunk_text": 切好的文本块, "chunk_id": 唯一标识符}`。

**提示**：你以后用 LangChain 或 LlamaIndex 做 RAG，它们底层的 `TextSplitter` 就是这么实现的。你能手写出这个，说明你真的懂 RAG 的数据流。

### 练习三：脏图片洗数据流水线（CV工程落地）

**业务背景**：用户上传的证件照/商品图，格式简直是灾难：有 JPG 的、有 PNG 带透明通道的、有纯灰度的，甚至有的尺寸高达 4000x3000。你要统一处理给视觉模型。

**技术要求**：
1.  **自定义 Dataset**：写一个 `DirtyImageDataset` 类。它接收一个图片文件夹路径。
2.  **容错机制**：在 `__init__` 或 `__getitem__` 里，用 `try-except` 包住图片读取逻辑。如果某张图用 `PIL` 打不开（损坏文件），直接跳过。
3.  **强制转换**：不管原图是什么通道（RGBA、L、CMYK），全部用 `.convert("RGB")` 强制转成三通道。
4.  **Transforms 组合**：定义一个 transform，先切中心，再缩放 `224x224`，最后转 Tensor 并 Normalize。
5.  **高级要求**：使用 `DataLoader` 的 `num_workers=4` 测试多线程加载，看看是否能在 1 秒内打包出多个 Batch。

def my_collate_fn(batch):
    # batch 是一个列表，里面是多个字典：[{'text': '...', 'label': 1}, ...]
    texts = [item['text'] for item in batch]
    labels = torch.tensor([item['label'] for item in batch])
    
    # 用 tokenizer 批量处理，指定 padding=True 自动补齐
