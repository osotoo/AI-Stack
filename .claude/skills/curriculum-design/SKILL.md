# 课程设计规范（curriculum-design）

本规范管"课怎么排"：一个学习阶段（层）拆成哪些小节、按什么顺序、怎么验收。单节怎么教归 `tutorial-writing`，本规范是它的上一层。

## 一、逆向设计三步（Wiggins & McTighe）

排任何一层的内容，顺序定死，不许颠倒：

1. **先定学习结果**：读完这一层，学习者能做出什么？（本仓库例：数据层 = "能构造出可被 `datasets` 加载的 100 条指令对"）。结果必须可验收，"了解 RAG"不算结果，"能搭一个带评测的 RAG 问答"才算
2. **再定评估证据**：什么证据证明学会了？每层至少一个**贯通验收项目**（数据层验收 = 练习 3；它能同时检验清洗和构造两个单点能力）。没有验收的学习活动是娱乐
3. **最后排学习活动**：有了目标和验收，再设计小节、阅读材料、练习——所有活动都要能回答"它在为哪个验收结果服务"

反例：先想"要讲哪些概念"再凑练习，就是顺序颠倒——练习会沦为概念的搬运工。

## 二、层的结构设计（scope and sequence）

1. **学习地图先行**：每层开工前先画表——小节、定位（必须动手/概念即可/选学）、先修依赖、产出、验收。先和用户对齐这张表，再逐节填充（本仓库的数据层就是这么做的）
2. **先修依赖显式化**：每个小节声明它依赖前面哪些小节的产出；依赖链写进层的 README（练习路径部分）。跨层依赖也显式写（如 RAG 的 chunking 依赖 p3 的文本处理手感）
3. **小节切分标准**：一个小节 = 一个可独立验收的能力点。切太碎（一节讲不清一个完整能力）或太粗（一节塞多个验收点）都要拆并
4. **深度分级写明**：哪些必须动手、哪些概念即可、哪些选学——对齐仓库 README 的学习深度要求，别默认全都要动手

## 三、排序原则

1. **由具体到抽象**：先动手摸到东西，再总结方法论（先清洗 30 条脏数据，再学"变换在前判等在后"的普适原则）
2. **由已知到未知**：新层开头必须挂上学过的层（学 RAG 前先勾 p5 的推理概念）
3. **螺旋式加深**：核心概念允许重复出现，但每次必须有新增量——第一次见格式，第二次手写，第三次上工具，第四次谈工程权衡。同难度复读不算螺旋
4. **间隔与交错**：验收项目和练习故意回收前面层/节的技能（数据层验收要用到 pandas 和正则——p1 阶段的技能），安排跨层回勾
5. **单点先于贯通**：每层的练习先做单点（每节自己的练习），最后汇到一个贯通项目验收；贯通项目依赖单点的产出

## 四、评估设计

1. **评估分层**：节级自测（检索练习，答案在上文）→ 层级贯通验收（可运行的产物 + 明确判据）→ 阶段对照（贯穿项目，如微调后的模型真的变好）
2. **验收判据可执行**："能被 `datasets` 库加载"、"统计数字对得上埋雷清单"——跑一下就知道过没过；"理解了"不是判据
3. **踩坑即评估**：刻意埋的认知雷（如近重复数据）本身就是检查点——踩了说明顺序没想清，对答案就完成一次反馈闭环

## 五、反模式

1. **内容先行**：先列概念清单再配练习，验收形同虚设
2. **线性堆砌无贯通**：只有一节节往下走，最后没有一个把所有能力拧在一起的项目
3. **先修不声明**：小节用到了没学过的东西且不承认依赖
4. **全是必做**：没有概念即可/选学的分级，学习者被平均用力拖死
5. **验收判据模糊**：拿"掌握了"、"熟悉了"当验收标准

## 六、设计完的自查清单

- 这层的验收项目，能同时检验到每个必须动手的小节吗？检验不到的小节要么并进验收、要么降级为概念即可
- 学习地图表（小节/先修/产出/验收）齐了吗？
- 有没有哪个概念出现两次但难度没升？有就删掉第二次
- 跨层依赖都写进对应 README 了吗？
- 每个验收判据都能"跑一下就知道过没过"吗？
