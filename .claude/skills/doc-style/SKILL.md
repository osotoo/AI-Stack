# 中文文档写作规范（doc-style）

本仓库全部中文文档遵循以下规范。规则来源：《中文文案排版指北》（sparanoid/chinese-copywriting-guidelines）、《中文技术文档写作风格指南》（zh-style-guide）。

## 一、排版硬规则

1. **中英文之间加空格**：`用 pandas 读 CSV`，不是 `用pandas读CSV`
2. **中文与数字之间加空格**：`洗出 22 条`，不是 `洗出22条`
3. **数字与单位之间加空格**：`10 GB`、`100 条`；百分比和度数除外（`15%`、`90°`）
4. **全角标点不与相邻字符加空格**：`用了 iPhone，很开心！`，不是 `用了 iPhone ，很开心！`
5. **用全角中文标点**：逗号句号问号用 `，。？`；引号用 `""`；括号用 `（）`（代码、专有名词内部除外）
6. **标点不重复**：不出现 `！！`、`？？`
7. **数字用半角**：`100`，不是 `１００`
8. **英文整句内部用半角标点**：「Stay hungry, stay foolish.」
9. **专有名词保持官方大小写**：GitHub、PyTorch、JSONL、OpenAI、Hugging Face；不写 github、jsonl、huggingface
10. **不用不道地的缩写**：写 `transformers 库`，不写 `tf 库`；写 `文档`，不写 `doc`
11. **不用 emoji**（全仓库约定，见 CLAUDE.md）
12. **句子长度**：不含标点不超过 20 字为宜；超长句拆成短句

## 二、结构与视觉软规则

1. **开头讲人话**：每个文档用 1～3 句自然语言开头，说清"这一节解决什么问题、为什么值得学"，不要一上来就是表格或术语清单
2. **结论前置**：每个小节第一句就是结论，展开和例子跟在后面；读者只看每段第一句也能读完骨架
3. **关键考点讲成例子**：抽象规则配一个具体的小故事或代码块（如"两条只差一个空格的文本"），让人看得见场景
4. **表格节制**：表格只装真正需要"对照"的信息（多行多列对比）；叙述性的内容用段落和列表，不要把段落塞进表格
5. **标题层级守纪律**：文件标题一级、章二级、节三级；尽量不用四级以下标题，用加粗或列表代替
6. **代码块包住一切示例**：命令、文件内容、输出、数据样例，一律用代码块，不和正文混排
7. **重点标记统一**：考点用 `（考点）` 标在标题末尾；核心结论用加粗；不发明新的标记花样
8. **列表不超两层**：嵌套超过两层说明该拆小节了

## 三、教学文档的固定骨架

层级 `README.md`（概括层）：人话开头 → 流程位置 → 本层重点（讲人话的几条） → 格式总表 → 子目录导航 → 练习路径 → 进度状态。

小节 `README.md`（教学层）：人话开头（本节解决什么问题）→ 一、知识学习（由浅到深，每节结论前置）→ 二、材料与脚本 → 三、课后练习（练习题 + 自测题 + 交作业一句话）→ 四、待补。
