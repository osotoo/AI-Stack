# p4_finetune — 模型生产·微调（路线图 ③）

把"会说话的基座"教成"会干活的模型"。不深入算法，但要亲手跑通一次微调闭环，理解 SFT / DPO / LoRA 各自解决什么问题。

## 流程位置

- **上游**：`p2_dataset`（训练数据）+ HuggingFace 基座模型
- **下游**：`p5_inference` —— 合并导出的模型权重交给推理层部署

## 子目录

| 子目录 | 内容 | 作用 |
|---|---|---|
| `p1_qlora/` | QLoRA SFT 实战 | 在 8G 显存约束下微调 Qwen2.5-0.5B/1.5B（**全参微调不可行**） |
| `p2_merge/` | LoRA 合并导出 | 把训练出的 LoRA 适配器合并回基座，产出完整权重 |
| `p3_dpo/` | DPO 偏好对齐【选学】 | 用偏好对数据做对齐训练，依赖 `p2_dataset/p3_preference` |

概念辨析（易混）：**SFT/DPO 是"训什么目标"（阶段先后），LoRA 是"怎么训省显存"（手段）**，两者正交、可组合。

## 学习深度要求

- **必须动手**：QLoRA 微调 Qwen2.5-1.5B-Instruct，验收标准：loss 下降，且回答比基座更贴合问答格式
- **概念即可**：预训练 → SFT → 对齐的三阶段分工、注意力机制黑盒认知

## 当前状态

- 待从零开始（PyTorch 基础见 `p3_pytorch/`）
- 衔接：`p2_merge` 产出 → `p5_inference/p3_quantize` 转 GGUF → 替换 `p7_agent` 里的现成模型，贯通项目闭环
