# p2_dataset — 数据工程（路线图 ②）

整个 AI 生产流程从数据开始。业内有句话叫"有多少人工，就有多少智能"：模型的能力上限由数据决定，你标注了多少数据、数据质量怎么样，直接框住了模型能学到什么。本层要做的事，就是把原始语料加工成能喂给微调的结构化数据集。

> 文件角色：本 README 只做概括提炼与导航。每个小节的完整教学和课后练习，在小节自己的 `README.md` 里。

## 流程位置

上游是起点，没有更上游；下游是 `p4_finetune`——本层产出的数据集就是微调的训练输入。

## 本层先记住三件事

**训练数据等于希望模型学会的行为。** 动手清洗或构造任何一条数据之前，先回答一个问题：我希望模型学会什么？这个答案决定 output 怎么写、脏数据怎么洗。

**三要素是数量、覆盖度、质量。** 数量最容易被高估——少量高质量数据可能比大量含噪数据表现更好；真正拉开差距的，往往是覆盖度，也就是数据的多样性。

**标准由下游决定。** 同一份语料，喂预训练、做 SFT、进 RAG 知识库，洗法完全不同。动手前先问：这批数据喂给谁？

还有一条递进链值得记住：标注难，定标注指南更难，自动生成数据难，自动验证质量最难。大公司设专职数据岗位，原因就在这里。

## 三个训练阶段的数据格式（考点）

| 训练阶段 | 数据格式 | 数据量衡量 | 本层对应小节 |
|---|---|---|---|
| 预训练 | 序列文本（自监督） | token 数 | `p1_corpus`（概念 + 清洗练习） |
| 监督微调 SFT | （指令，响应） | 样本数 | `p2_instruction`（核心动手节） |
| 偏好微调 DPO | （提示词，胜出响应，落败响应） | 样本数 | `p3_preference`（选学） |
| 奖励模型 | 偏好格式，或（（指令，响应），分数） | 样本数 | `p3_preference` |

预训练按 token 数算账，微调按样本数算账——这是两个阶段的第一处分野。

## 练习路径：先单点，后贯通

先做单点练习：`p1_corpus` 的清洗，`p2_instruction` 的格式热身和模板构造。然后做本层的验收项目——`p2_instruction` 练习 3：亲手构造 100 条指令对，能被 `datasets` 库加载即通过。最后是选学的偏好对练习。

交作业统一三样：`.py` 放对应小节目录、发控制台输出、说踩坑点。

## 学习深度要求

- 必须动手：亲手构造 100 条指令对（Excel 转 JSONL），验收标准是能被 `datasets` 库加载
- 概念即可：预训练语料的规模量级、工业级清洗去重流程
