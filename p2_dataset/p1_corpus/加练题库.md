# p1_corpus 加练题库

配合 README 练习区的日历用：第一、二波插在第 4、5 天，第三波插在第 7 天复测之后，第四波在站 4 贯通之后做。

做题节奏和站 3 相同，三步固定：先在纸上报招式，再写代码跑，最后翻到文末答案区对数字。没报招式就动手的题，做完等于白做。

除特殊注明外，第一到第三波都从原始 `raw_corpus.csv` 的 30 条读起；第四波读 `raw_corpus_v2.csv` 的 15 条。

## 第一波：单招（10 题）

招式表五行，一题一招，故意打乱了顺序：

1. 删掉 source 是"客服工单"的所有行
2. 每个 source 各有多少条
3. 把 text 里的"退款"全部替换成"退货退款"
4. text 含"物流"的行有几条
5. 精确去重（整份原始数据）
6. 四种空值各几条：NaN、纯半角空格、纯全角空格、非空
7. 把 source 列里的"客服工单"改名为"工单"
8. 删掉 text 含"发货"或"物流"的行
9. text 含"好"字的行有几条
10. 找出 text 最长的一条，打印它的 id

## 第二波：组合招（7 题）

一题要连用两招，想清楚先后：

11. 去空、再精确去重，剩几条
12. 先去首尾空白，再去空、去重，剩几条
13. 给 text 含"发票"的行统一加上前缀 `[需人工复核] `（提示：`df.loc[mask, "text"] = ...`）
14. 每个 source 里，text 含"退"的行各几条
15. 去掉全部 HTML 标签之后，text 最长的行变成哪条
16. 去空后的 27 条里，客服工单还剩几条
17. 只去首尾空白（不去重），哪两行变得一模一样

## 第三波：带雷（6 题）

每题先自己跑、先自己解释，再看答案。踩雷不是失败，雷就是这波的考点：

18. 用 `str.replace(" ", "")` 把半角空格删光再判空，能抓到 id=27 的全角空格行吗
19. 用正则 `r"\d{11}"` 判断"是否手机号"，会误伤哪几行
20. 不用 pandas，用 `open()` 加 `split(",")` 读 CSV，行数还是 30 吗
21. `drop_duplicates()` 不带参数，和 `drop_duplicates(subset=["text"])`，各剩几条（都先去空）
22. `df["text"].str.contains("发票")` 遇到 NaN 行返回什么？对筛选和计数有影响吗
23. id=25 和 id=10 的 text 完全相同但 source 不同：按 text 判等会删它，按整行判等会留它。站在指令对构造的立场，该删还是留，为什么

换一批没见过的数据 `raw_corpus_v2.csv`，15 条，这批没有埋雷清单——雷要自己找。先自己扫一遍数据，把发现的雷列在纸上，再做题：

T1. 去空，剩几条
T2. 删掉含 URL 的行，剩几条
T3. 把邮箱地址脱敏成 `[EMAIL]`，几行变化
T4. 去掉表情符号，几行变化
T5. id=4 和 id=9 是近重复，要把它们收编成一条，最少要用上哪几招

T7. 贯通加餐：去掉 HTML 标签后的老语料 27 条，和去空后的 v2 合并，按 text 精确去重，剩几条

## 答案区

做题之前别往下翻。

**第一波**

1. 剩 16 条
2. 客服工单 14、在线评论 11、问卷反馈 5
3. 2 行变化（id=1、9），30 条不变
4. 2 条（id=6、17）。注意 id=18 是乱码行，它"长得像"物流数据但字符上不含这两个字——乱码行做检索题时要小心
5. 剩 26 条（30 减 4 条多余重复）
6. NaN 1（id=3）、纯半角空格 1（id=12）、纯全角空格 1（id=27）、非空 27
7. 14 行变化
8. 剩 27 条（删掉 id=2、6、17）
9. 2 条（id=6、20）
10. id=17——`<span style="color:red">` 这串标签把它撑到全场最长。教训：长度要洗完再量

**第二波**

11. 剩 23 条。id=14 和 id=23 双双存活，顺序雷还在
12. 剩 22 条。id=23 被收编
13. 3 行变化（id=5、19、26），30 条不变
14. 在线评论 3、客服工单 2、问卷反馈 0
15. 变成 id=9。去掉标签后 id=17 只剩 15 个字符
16. 剩 12 条（原始 14 条减去被去空的 id=3、12）
17. id=14 和 id=23。"变换在前、判等在后"讲的就是这对数据

**第三波**

18. 抓不到。replace 只认半角空格，全角空格"　"不等于" "。判空用 strip 才安全
19. 误伤 id=2（订单号前 11 位）、id=9、id=29（两个身份证号）。手机号必须加"1 开头"和左右边界约束
20. 不是。物理行变成 31：id=24 字段内的换行把一行拆成两行；id=28 的半角逗号把一行错切成三段。这就是要用 pandas 或 csv 模块解析的原因
21. 整行判等剩 24 条，按 text 判等剩 23 条。差的就是跨来源重复 id=25
22. 返回 NaN。布尔筛选把 NaN 当 False，所以筛选不报错、含"发票"照常是 3 条——但这属于侥幸，严谨写法是 `str.contains("发票", na=False)` 把 NaN 显式当 False
23. 开放题。本仓库立场：指令对构造阶段按 text 判等，id=10 留、id=25 删——同一句话教两遍没有增量价值，来源不同不改变这一点

**第四波**

先对扫雷清单：空字段 1（id=3）、纯全角空格 1（id=10）、URL 2（id=1、7）、邮箱 2（id=2、11）、表情 3（id=4、6、9）、引号包裹的半角逗号 1（id=12）、中英混杂 1（id=7）、近重复 1 组（id=4、9）、纯标点 1（id=13）、座机 1（id=15）、跨语料重复 2（id=8 等于老语料 id=26；id=14 去标签后等于老语料 id=17）

T1. 剩 13 条（删 id=3、10）
T2. 剩 11 条（删 id=1、7）
T3. 2 行变化（id=2、11）
T4. 3 行变化（id=4、6、9）
T5. 三招齐下：去表情、去首尾空白并压掉连续空白，然后去重。少任何一招都收编不了——id=9 和 id=4 差了两处
T6. 不会。座机 0 开头，不满足"1 开头加边界"约束；id=11 的 13800138000 才是真手机号，会被正确命中。这正是第三波第 19 题教训的正确迁移
