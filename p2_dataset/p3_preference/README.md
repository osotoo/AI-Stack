## 一、知识学习

### 1.1 DPO 数据格式（考点）

偏好微调需要 **（提示词，胜出响应，落败响应）** 三元组，数据量按样本数衡量。JSONL 每行一条：

```json
{"question": "怎么退换货？", "chosen": "分步说明：1. 先在订单页… 2. …", "rejected": "去订单页面看看。"}
```

### 1.2 奖励模型（RM）的数据格式

训练奖励模型可用的两种格式：
- 偏好格式（和 DPO 一样）
- **（（指令，响应），分数）** 带标注分数的格式

### 1.3 标注：人是裁判

- `chosen` / `rejected` 由人标注——同一个问题收集 2~3 个不同质量的回答，人来判断优劣
- 动手前先写**标注指南**（什么样的回答算胜出？）——**制定标注指南比标注本身更难**，这是数据工作难度的核心递进：标注难 → 定指南更难 → 自动生成难 → **自动验证质量最难**
- 造档差的常用手法：同一问题让模型分别生成"详细分步"和"一句话敷衍"两个版本，天然拉开质量差距

1. 挑 10 个问题，对每个问题收集 2~3 个不同质量的回答（用 Ollama 不同 prompt 生成：一个要求"详细分步"，一个要求"一句话敷衍"）。
