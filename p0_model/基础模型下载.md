# Base模型下载与Ollama格式转换实战指南

## 🎯 背景与目标
*   **目标**：将 Hugging Face 上的原生基础模型（Base 模型，无安全对齐与指令微调）下载至本地，转换为 Ollama 支持的 GGUF 格式，并在 Ollama 中加载运行。
*   **使用模型**：`Qwen/Qwen2.5-1.5B` （注意：无 `-Instruct` 后缀，代表纯原始底座）。
*   **运行环境**：Windows + Anaconda (`ai-stack`) + Git Bash / PowerShell。

---

## 🛠️ 操作步骤

### 第一步：从 Hugging Face 下载 Base 模型
由于官方源访问受限，需配置国内镜像站。
**注意**：如果在 Git Bash 中操作，路径请使用正斜杠 `/`；如果在 PowerShell 中，请使用反斜杠 `\`。

```bash
# 设置环境变量走国内镜像
export HF_ENDPOINT="https://hf-mirror.com"

# 使用 huggingface-cli 或 hf 命令下载模型到指定目录
huggingface-cli download Qwen/Qwen2.5-1.5B --local-dir /d/coding/ai-stack/p0_model/Qwen2.5-1.5B-Base
```

> **踩坑记录**：如果遇到 `SSLError` 或 `FileMetadataError`，且报错指向 Xet 存储协议，可尝试设置 `export HF_HUB_DISABLE_XET=1` 禁用加速，或清理目标文件夹下的 `.cache` 隐藏目录重试。

### 第二步：准备 llama.cpp 转换工具
Ollama 的底层推理引擎（llama.cpp）只认 GGUF 格式，需使用官方脚本转换。

```bash
# 1. 将 llama.cpp 源码克隆到本地（或直接下载 ZIP 解压）
git clone https://github.com/ggerganov/llama.cpp.git
cd llama.cpp

# 2. 安装转换脚本所需的 Python 依赖
pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

### 第三步：执行格式转换（HF -> GGUF）
保持当前终端在 `llama.cpp` 目录下，执行转换脚本。

**核心死命令**：路径中绝对不能用 Windows 的反斜杠 `\`，否则会被当成转义字符导致路径解析错误。

```bash
# 命令格式
python convert_hf_to_gguf.py <HF模型目录绝对路径> --outtype f16 --outfile <输出GGUF文件绝对路径>

# 实际执行命令（Git Bash环境）
python convert_hf_to_gguf.py /d/coding/ai-stack/p0_model/Qwen2.5-1.5B-Base --outtype f16 --outfile /d/coding/ai-stack/p0_model/Qwen2.5-1.5B-Base/Qwen2.5-1.5B-Base-F16.gguf
```
*转换完成后，模型目录下会生成一个约 3GB 的 `.gguf` 文件。*

### 第四步：通过 Modelfile 导入 Ollama
Ollama 无法直接吃文件夹，必须通过 `Modelfile` 注册。

```bash
# 1. 切回模型目录
cd /d/coding/ai-stack/p0_model/Qwen2.5-1.5B-Base

# 2. 创建无后缀名的 Modelfile 文件
# 文件内容仅一行：
FROM ./Qwen2.5-1.5B-Base-F16.gguf

# 3. 执行创建命令，给模型起个名字（如 qwen-base）
ollama create qwen-base -f Modelfile

# 4. 运行并测试
ollama run qwen-base
```

## 🚨 核心观察与现象记录（面试必考点）

1.  **Base 模型的“智障”表现**：
    *   输入“1+1等于几”或给定的 Few-shot 格式提示词，模型没有直接回答问题，而是不断输出 `.createObject` 或类似 JavaScript 代码的片段。
    *   **原理解析**：Base 模型没有经过人类指令对齐（Instruct Tuning），它只做“纯粹的文字接龙”。在它的预训练语料库中，上述提示词后面出现 `.createObject` 的概率最高，因此产生死循环式的复读。
2.  **指令模型（Instruct）的价值**：
    *   这证明了 `RAG（检索增强生成）` 和 `Prompt Engineering` 的有效性，必须建立在模型已经具备基础对话能力（即经过 SFT 微调）的前提上。

---

## 💡 架构师总结
*   **微调的本质**：微调（Fine-tuning）就是拿带有“标准答案（Label）”的指令数据，去强制纠正这种文字接龙的概率分布，让模型学会“看到问句必须回答，且遵循特定格式”。
*   **业务选型优先级**：企业应用优先用 `Instruct模型 + RAG + Prompt`。只有遇到极度要求格式服从、特有行业推理逻辑或极限降本（大模型教小模型）时，才考虑动用算力进行微调。
