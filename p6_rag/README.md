# p6_rag — 应用工程·RAG 检索增强（路线图 ⑤）

给模型**外挂知识库**，解决两个痛点：私域知识模型不知道、硬答会幻觉。RAG 是应用工程的核心技能，也是企业知识库场景最常用的落地形态。

## 流程位置

- **上游**：`p5_inference` 提供的模型 API（Embedding / Rerank / Chat 各用各的）
- **下游**：`p8_governance` 对检索与回答质量做评测

## 子目录（= RAG 管道顺序）

| 子目录 | 内容 | 作用 |
|---|---|---|
| `p1_chunking/` | 分块策略 | 文档切块的粒度与方式，直接决定检索颗粒度 |
| `p2_embedding/` | Embedding 选型 | 把文本变向量（bge 系等），选型影响召回质量 |
| `p3_vectorstore/` | 向量库 | Milvus / PgVector，向量存储与 ANN 检索 |
| `p4_search/` | 混合检索 | BM25 关键词 + 向量语义，互补提升召回 |
| `p5_rerank/` | 重排 | 对初筛结果精排，把最相关的顶到最前 |
| `p6_spring_rag/` | Spring AI 全链路 | 用 Java 把上述管道串成可用的问答服务 |

关键认知：**向量库只是存储，检索质量由分块/Embedding/混合检索/Rerank 决定**——调优精力应该花在管道上，不是换库上。

## 学习深度要求

- **必须动手**：每个环节各跑通一次，最终 `p6_spring_rag` 出一个完整 demo
- **概念即可**：ANN 检索原理、各向量库差异
